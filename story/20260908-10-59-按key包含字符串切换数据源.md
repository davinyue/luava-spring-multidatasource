# 按 key 包含字符串切换数据源

## 背景

当前 `LuavaMultiDataSource` 仅支持根据完整数据源 key 切换，数据源 key 带有统一前缀或后缀时调用不够方便。

## 目标

增加根据完整数据源 key 或 key 包含指定字符串获取数据源的便捷方法，并支持通过事件进行包含字符串切换；修复从库轮询在数据源动态重载时的状态问题；补全相关 JavaDoc 注释。

## 范围

- 在 `LuavaMultiDataSource` 中新增包含匹配字符串的数据源切换方法。
- 在 `LuavaMultiDataSource` 中新增根据完整 key 和包含 key 获取数据源的方法。
- 新增根据包含字符串切换数据源的事件。
- 在数据源监听器中区分完整 key 事件和包含字符串事件。
- 修复从库列表重载、轮询下标和并发访问问题。
- 补全类、字段、构造方法及方法的 JavaDoc 注释。
- 保持现有参数校验和未匹配时回退主库的行为。

## 非目标

- 不调整现有精确 key 切换、从库轮询或 AOP 切换逻辑。
- 不新增依赖或修改数据源配置格式。
- 不改变现有精确 key 事件的行为。
- 不改变手动切换时 ThreadLocal 的生命周期语义。

## 关键设计

新增 `markByKeyContains` 方法，按从库 key 的配置顺序查找第一个包含指定字符串的 key，并复用现有 `markByKey` 完成切换；没有匹配项时调用 `markMaster`。新增 `getDataSourceByKey` 和 `getDataSourceByKeyContains` 方法，从 Spring 已解析的数据源映射中返回对应数据源，未匹配时返回主数据源。

新增 `SwitchDataSourceContainsEvent`，继承 `SwitchDataSourceEvent` 以复用事件参数校验和 Spring 监听入口；监听器收到该事件时调用 `markByKeyContains`，收到普通事件时仍调用 `markByKey`。

从库 key 列表每次重载时重新构建并将轮询下标重置为 0；从库列表使用可见性保证，`markSlave` 在同步区域内读取列表并在取值前校正下标，避免动态缩容造成越界。

## 验收标准

- 指定字符串为空或 null 时抛出参数异常。
- 能切换到第一个包含指定字符串的从库 key。
- 没有匹配项时切换到主库。
- 能根据完整 key 获取对应数据源。
- 能根据包含字符串获取第一个匹配的数据源。
- 发布 `SwitchDataSourceContainsEvent` 后能按包含字符串切换数据源。
- 发布 `SwitchDataSourceEvent` 时仍按完整 key 切换数据源。
- 动态重载为无从库时不会继续使用旧从库 key。
- 动态缩减从库数量后不会因轮询下标过大而越界。
- `LuavaMultiDataSource` 的类、字段、构造方法及方法均有完整 JavaDoc 注释。
- 项目能够通过 Maven 编译。

## 当前进度

已完成 `markByKeyContains`、`getDataSourceByKey` 和 `getDataSourceByKeyContains` 方法、`SwitchDataSourceContainsEvent` 事件、监听分发逻辑，以及 `markSlave` 动态重载安全修复；Maven 编译、JavaDoc 生成和差异检查均已通过，待用户确认需求完成。

## 风险与阻塞

暂无阻塞。多个匹配 key 时按配置顺序使用第一个匹配项；手动切换后的 ThreadLocal 状态仍需由调用方按作用域恢复。
